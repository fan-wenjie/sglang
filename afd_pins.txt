# The CUDA wheels must agree with each other or CCCL refuses the pair at JIT time with
# "CUDA compiler and CUDA toolkit headers are incompatible" -- which reads as a broken install
# and is a version skew between two wheels. It happened twice: once on the first install, and
# again when `pip install accelerate` quietly pulled nvidia-cuda-runtime back from 13.3 to 13.0.
#
# Reapply after ANY pip install in this environment:
#     python -m pip install -r afd_pins.txt
# and check with:
#     grep -m1 CUDART_VERSION $CU13/include/cuda_runtime_api.h    # must read 13030
nvidia-cuda-runtime==13.3.*
nvidia-cuda-nvrtc==13.3.*
nvidia-cuda-cupti==13.3.*
nvidia-cuda-nvcc==13.3.*
nvidia-cuda-crt==13.3.*

# `cuda-toolkit` is a meta-package that pins nvrtc to the 13.0 line, and the host env carries both
# it and the 13.3 wheels because the pins were force-applied on top. pip cannot resolve that pair
# from a freeze: reproducing this environment means dropping cuda-toolkit and installing the
# individual nvidia-* wheels, which is what the host actually runs.

# A freeze filtered with `grep -v '^sglang'` also drops `sglang-kernel`, which is a different
# package -- the compiled kernels, imported as `sgl_kernel`. The second machine got everything
# else and failed at the first quantised layer with ModuleNotFoundError, half an hour after the
# install reported success. Install it by name:
#     python -m pip install sglang-kernel==0.4.6.post1
# then reapply the pins above with --no-deps.
